## 1. Proposition 9.1 and Hausdorffness

**Decision: REJECTED.**

The inclusion
[
\operatorname{Cl}_{\mathrm{fin}}(S)\subseteq\overline S
]
uses only the basis property of the product topology: a basic neighborhood restricts finitely many coordinates. Hausdorffness is not needed.

Hausdorffness is required later for the compact-image argument, where a compact subset of the response product must be closed.

**Patch:** add an explicit remark separating these two roles.

If (R_P) is continuous into a metric response space, then

W\mapsto d_P(R_P(W),y_P)

## 3. Sparse moment benchmark

**Decision: ACCEPTED WITH CORRECTIONS.**

Let the model class be finitely supported probability measures on (mathbb R), the protocols be polynomial moments, and the target profile be generated by (N(0,1)).

### Finite consistency

Accepted.

For any finite set of moment protocols, exact matching by a positive finitely supported probability measure follows from Tchakaloff-type cubature. A convenient reference is:

C. Bayer and J. Teichmann, *The proof of Tchakaloff's theorem*, Proc. AMS 134(10) (2006), 3035–3040. DOI: 10.1090/S0002-9939-06-08249-9.

Therefore
[
\delta_{\mathrm{fin}}(y)=0
]
for every positive protocol-scale family.

### No exact global sparse realization

Accepted.

Any finitely supported probability measure has bounded support, so its even moments grow at most exponentially as (R^{2m}). Gaussian even moments
[
(2m-1)!!
]
eventually dominate (R^{2m}) for every fixed (R). Hence no finite-atomic probability measure reproduces all Gaussian moments.

### Raw calibration

Accepted after correcting the min-max order.

For (sigma_n=1), every admissible atomic measure has
[
\sup_n |R_n(\nu)-y_n|=\infty,
]
hence
[
\delta_{\mathrm{glob}}(y)=\infty.
]

The reviewer wrote a swapped expression `sup_n inf_mu`; WR-II uses
[
\inf_\mu\sup_n.
]

### Relative calibration

A sharper finite positive example is available:
[
\sigma_n=\max\{1,|y_n|\}.
]
Then
[
\delta_{\mathrm{fin}}=0,qquad
\delta_{\mathrm{glob}}=1,qquad
\Gamma=1.
]

This is proved by comparing every atomic even-moment sequence to Gaussian moment growth, while the model (delta_0) attains global residual 1.

### Factorial calibration

The review's suggestion is directionally correct but too vague. With
[
\sigma_n=n!,
]
N-point Gauss-Hermite quadrature yields
[
\delta_{\mathrm{glob}}=0
]
while no exact global realization exists. Thus
[
\Gamma=0
]
and the defect survives purely as nonattainment.

This is a stronger illustration than saying the radius “may be finite.”

## 4. Interpretation of protocol scales

**Decision: PARTIALLY REJECTED.**

The protocol scales (sigma_P) are not Tikhonov regularizers.

They define the geometry of the **data-fidelity / response discrepancy**. For independent measurement noise they may be derived from per-protocol standard deviations; correlated noise generally requires bundle-level covariance metrics.

Tikhonov regularization instead adds a penalty/prior geometry on the model variable. The two mechanisms may coexist but should not be identified.

**Patch:** add a terminology firewall.

## 5. Model misspecification interpretation

**Decision: PARTIALLY ACCEPTED.**

The sparse moment example supports the phrase:

> protocol-relative finite-to-global model-class mismatch diagnostic.

It does **not** justify calling (Gamma) a universal or calibration-independent misspecification metric. The same exact model mismatch can give:
- infinite global radius;
- a finite positive gap;
- zero global radius with nonattainment;

under non-uniformly equivalent response calibrations.

This calibration dependence is a feature to be exposed, not hidden.

## 6. L-infinity versus L2

**Decision: PARTIALLY ACCEPTED.**

The supremum over protocols encodes uniform per-protocol feasibility. An (L^2) or covariance-weighted integrated norm requires an additional measure/covariance structure on protocol space and answers a different question.

**Patch:** retain the sup-norm layer as the canonical WR-II finite/global construction; add measure-aggregated response norms as a downstream extension.
